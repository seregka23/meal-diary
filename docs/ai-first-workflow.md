# AI-first task hand-off

Use the task output generated by the `ai_first` approach as the input to the
orchestrator. Preserve its parent tasks, subtasks, dependencies, and acceptance
criteria. Adapt the file path if your generator uses a different convention.

## Minimum quality of an executable task

Each task should include:

1. A user-visible goal.
2. Explicit acceptance criteria.
3. Bounded parent tasks and subtasks.
4. Dependencies or ordering constraints.
5. Out-of-scope items where useful.

## Execution prompt

```text
Implement all unfinished work in <task-file>.
Use it as the source of truth; do not create a competing plan.
Act as the orchestrator. Delegate only independent bounded work to backend,
frontend, and tester. Run reviewer after implementation and testing.
Update the task's completion record only when every acceptance criterion is
demonstrably met and all available checks pass.
```

## Practical convention

Keep generated tasks in a branch with the implementation. This lets a review
show both the code diff and the exact criteria that governed it.
